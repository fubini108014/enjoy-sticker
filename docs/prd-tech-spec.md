# **1\. 執行摘要與商業設定 (Executive Summary)**

## **產品定位與商業模式**

本平台專注於消費級（C 端）與個人文創的「零門檻線上貼紙編輯與訂製平台」。用戶只需上傳圖片，系統將自動完成去背、生成邊框刀模與緊湊排版，降到最低的操作門檻。

營運初期採\*\*輕資產自營工坊（Micro-Factory / Studio）\*\*模式，透過桌上型高階相片噴墨印表機與數位割字機，在家或小型工作室完成全流程生產（印刷、覆膜、模切、包裝與寄送），達到極低固定成本與快速驗證市場之目的。

## **主力商品與目標市場**

* **主力銷售單位**：A4 整版拼貼板（Sticker Sheet，採用 Kiss-cut 半斷工藝）。  
* **目標市場**：台灣本地市場，全面支援新台幣 (TWD) 計價、本地主流第三方金流、超商取貨與郵局扁平件物流。

# **2\. 實體產線與設備整合規格 (Hardware & Manufacturing Spec)**

## **2.1 推薦硬體配置**

1. **印刷設備**：`Epson L8050`（A4 六色連續供墨）。採用 C, M, Y, K, Lc, Lm 6 色墨水，可有效消除人物膚色與漸層色彩的顆粒感。  
2. **裁切設備**：`Silhouette Cameo 4 / 5`。內建光學對位感測器，支援 Print & Cut 巡邊自動裁切。  
3. **覆膜設備**：手動冷裱覆膜機（350 mm 滾軸幅寬）。

## **2.2 裁切工藝與對位規範（Silhouette Registration Standard）**

後端渲染產出的 A4 印刷檔，四周必須嚴格保留 Silhouette 割字機光學鏡頭讀取記號（Registration Marks）的專用禁印區域：

* **標記樣式**：  
  * 左上角：實心黑色方塊（\$5 \\times 5 \\text{ mm}\$）。  
  * 右上角與左下角：各有一組直角「L」型光學定位線。  
* **物理邊界限制**：  
  * 上方預留 \$15 \\text{ mm}\$，左右預留 \$10 \\text{ mm}\$，下方預留 \$20 \\text{ mm}\$。  
  * **有效排版安全區域**：寬約 \$180 \\text{ mm} \\times\$ 高約 \$250 \\text{ mm}\$。  
  * 光學讀取通道（所有對位記號周圍 \$10 \\text{ mm}\$ 半徑內）嚴禁有任何彩色圖案或文字。  
* **刀模工藝參數**：  
  * **半斷（Kiss-cut）**：僅切穿貼紙層與背膠層，底紙保持完整不切穿。  
  * **容差邊界**：貼紙輪廓白邊預設寬度為 \$2.0 \\text{ mm}\$，以吸收割字機運作時約 \$\\pm 0.3 \\text{ mm}\$ 的機械偏差。

* \*\* API 閘道器\*\*：`NestJS / Node.js` \+ `PostgreSQL` \+ `Prisma ORM` \+ `Cloudflare R2`（圖檔儲存）+ `BullMQ`（非同步任務佇列）。  
* **渲染與演算法 Worker**：`Python FastAPI` \+ 開源去背模型（`BiRefNet` / `RMBG-1.4`）+ 向量演算法（`Clipper2` / `Shapely`）+ PDF/DXF 產出（`PyMuPDF` / `ReportLab` / `ezdxf`）。

# **4\. 核心功能規格詳細說明 (Functional Specifications)**

## **4.1 前端畫布編輯器模組 (Frontend Canvas Editor)**

1. **多格式上傳**：支援 JPG、PNG、WebP、HEIC（手機拍立得格式，由前端自動轉換為 PNG），單一檔案限制 \$25 \\text{ MB}\$。  
2. **DPI 智能防呆警告**：  
   根據貼紙在 A4 畫布上的實際物理尺寸（\$\\text{mm}\$）計算來源圖片像素密度：  
   \$\$\\text{實際 DPI} \= \\frac{\\text{像素寬度}}{\\text{物理寬度 (mm)} / 25.4}\$\$  
   * \$\\ge 300 \\text{ DPI}\$：顯示綠色優良標示。  
   * \$150 – 299 \\text{ DPI}\$：顯示黃色警示。  
   * \$\< 150 \\text{ DPI}\$：顯示紅色警告，並跳出「印製效果可能模糊」之提示。  
3. **刀模白邊控制器**：預設開啟自動白邊（\$1.0 – 4.0 \\text{ mm}\$ 可調）。提供「單圖填滿」與「多圖自動緊湊排列（Auto-pack，物體間最小間距 \$3 \\text{ mm}\$）」功能。

## **4.2 影像演算法與刀模管線 (Contour Generation Pipeline)**

\[原始圖檔\] ──► \[ Alpha 去背 (RMBG-1.4) \] ──► \[ 二值化遮罩 (Threshold 128\) \]

                                                        │

\[ 輸出 SVG/DXF \] ◄── \[ RDP 簡化與平滑 \] ◄── \[ Clipper2 膨脹 (+2mm) \] ◄── \[ Marching Squares 輪廓提取 \]

1. **AI 智慧去背**：輸入圖檔經由 RMBG-1.4 處理，產出 Alpha 通道遮罩。  
2. **二值化與輪廓提取**：採用 Marching Squares 演算法將 Alpha 通道轉換為多邊形邊界點陣列。  
3. **向量外擴（Offsetting）**：利用 Clipper2 進行多邊形正向膨脹，計算公式為預設白邊值 \$+2.0 \\text{ mm}\$。  
4. **節點簡化**：使用 Ramer-Douglas-Peucker (RDP) 演算法，將 \$\\epsilon\$ 設為 \$0.8 – 1.2 \\text{ px}\$，去除過度密集的節點。  
5. **平滑化處理**：採用 Chaikin 演算法或 Cubic Bézier 曲線進行邊角平滑。

## **4.3 檔案匯出規格 (Export Standard)**

* **`order_{id}_print.pdf`（列印專用檔）**：  
  * 尺寸：標準 A4（\$210 \\times 297 \\text{ mm}\$）。  
  * 解析度與色彩：\$300 \\text{ DPI}\$、CMYK 色彩空間（嵌入 FOGRA39 描述檔）。  
  * 內容：包含 Silhouette 光學對位記號、圖檔本身、及 \$0.5 \\text{ mm}\$ 出血位，**不含**裁切紅線（防止誤印切線）。  
* **`order_{id}_cut.dxf` / `.svg`（割字機專用刀模檔）**：  
  * 比例：1:1 等比例對齊。  
  * 內容：包含三點對位記號點位，以及 \$0.1 \\text{ pt}\$ 紅色閉合向量切線（`#FF0000`）。

* **階段 1：核心演算法驗證 PoC（第 1–2 週）**  
  * 搭建 Python Worker 服務，驗證去背、輪廓導出與 Clipper2 膨脹計算。

  * 完成前端 Fabric.js 編輯器開發，實現即時白邊預覽與排版。  
  * 實現高解析度 CMYK PDF 生成，並進行實體 Epson L8050 印刷與 Cameo 裁切對位測試，校正機械誤差。

# **8\. 產能瓶頸與產線升級路徑 (Scaling Strategy)**

小作坊期 (1-15張/日)     ──► 單人作業 / 單機 L8050 \+ Cameo 4

微型工廠期 (20-50張/日)  ──► 雙裁切機並行 \+ 電動冷裱機 \+ 局部備貨

外包轉移期 (50+張/日)    ──► 啟動代工廠 API 自動拋單 (BPO)

1. **小作坊期（第 1–2 個月，日單 1–15 張，月營收約 0.6–9 萬）**  
   * **設備**：Epson L8050 \$\\times\$ 1、Cameo 4 \$\\times\$ 1、手動冷裱機 \$\\times\$ 1。  
   * **人力**：創辦人單人兼職營運，手工覆膜與包裝。  
2. **微型工廠期（第 3–4 個月，日單 20–50 張，月營收約 12–30 萬）**  
   * **設備**：添購第二台 Cameo 5 裁切機以舒緩瓶頸，升級為 380mm 電動自動進紙冷裱機。  
   * **流程優化**：後端新增批次列印功能，將多張 A4 訂單合併產出。  
3. **外包轉移期（第 5 個月後，日單 50+ 張，月營收 30 萬以上）**  
   * **策略轉型**：對接大型印刷廠 API（如健豪、雲端印刷網），將量大或複製訂單自動轉單外包（BPO）。  
   * **自營產線定位**：自營設備轉為處理「加價急件（24H 出貨）」與特殊小眾材質。

# **11\. 風險管理與應對預案 (Contingency Plans)**

| :---- | :---- | :---- |

# 13. MVP 產品體驗與履約補充規格（2026-10-03）

本章將產品經理檢視的建議納入開發範圍，補足第 1–12 章的使用者體驗、資料一致性、異常履約與驗證方式。本章涉及 MVP 時程、草稿、訂單快照與付款前檢查的規則優先於原章節；原章節硬體、金物流供應商與成本估算仍屬待驗證假設。專案介面原型是體驗驗證工具，不代表正式後端、印刷或金物流已完成。

## 13.1 目標族群與產品範圍

### 生活創作（MVP 主要族群）

使用者把毛孩、朋友、旅行與日常照片製作成不同圖案的貼紙。主要工作是上傳、選擇背景處理、設定大小、自由拼貼與確認訂製。產品成功條件是首次使用者可在無人工協助下完成一張願意購買的貼紙板。

### 小量商用（共用編輯器支援）

使用者將同一個 Logo 或插畫重複印製，重視尺寸、份數、整版容量與單價。提供「同圖份數」與「同圖排滿」，不在 MVP 增加企業帳號、複雜報價或大量生產流程。

MVP 收斂為 A4 白底防水貼紙與亮面／霧面兩種覆膜選擇；特殊材質、白墨、市集與創作者分潤留在第二階段。此處材質描述須經實體材料測試，正式頁面不可使用未驗證的耐候或防水承諾。

## 13.2 完整使用者流程

免登入開始 → 上傳／示範素材 → 保留原圖或去背 → 尺寸與白邊設定 → 自由拼貼／同圖排滿 → 印製檢查 → 確認材質與配送總價 → 提供必要收件與聯絡資料 → 建立訂單及設計快照 → 付款 → 生產 → 出貨 → 售後／重新訂購。

會員登入不可阻擋第一次上傳。必要聯絡資料在結帳時取得；正式系統提供安全的訪客訂單查詢方式，後續可將草稿與歷史訂單連結至帳號。

## 13.3 背景處理與影像錯誤

- 使用者可選「保留原圖」或「自動去背」，原圖不可因去背覆寫而遺失。
- 顯示原圖／結果比較；可還原原圖，之後再次去背。
- 任務包含等待、處理中、成功、失敗、逾時與重試狀態。失敗說明應告知下一步，不得把空白或錯誤圖像當成成功結果。
- 去背失敗時可換圖、重試或使用原圖繼續；原圖模式的刀模以矩形或使用者選定基本形狀處理，與主體輪廓刀模區分。
- 超出容量、無法解碼、格式不支援與尺寸不合理時，保留原畫布並顯示可修正的提示。
- 上傳只供製作訂單使用；正式系統另定來源圖、草稿、訂單檔案保存期限、刪除流程與存取權限。原型圖片不會上傳到伺服器。
- 手動擦除／修復筆刷列為後續改善；MVP 必須先具備選擇、比較、還原與失敗處理。

驗收：處理失敗不遺失原圖；快速切換選取圖案時，前一個任務不能改動新的圖案；重試不產生重複素材。

## 13.4 編輯器操作規則

| 功能 | 規則與驗收 |
| --- | --- |
| 寬高 | 以 mm 顯示寬與高，預設鎖定比例；調整結果同步更新 DPI。MVP 不提供任意拉伸。 |
| 移動與旋轉 | 可拖曳、點選及旋轉；選取後以四角控制點等比例縮放、上方把手旋轉，Shift 旋轉以 15° 刻度調整；側欄與畫布數值同步，鍵盤方向鍵微調。白邊與旋轉後的輪廓都須納入安全區檢查。 |
| 複製與刪除 | 單張複製、指定新增份數；刪除後可復原。 |
| 復原／重做 | 涵蓋移動、旋轉、尺寸、白邊、背景模式、複製、刪除與排版。失敗操作不寫入有效步驟。 |
| 同圖排滿 | 先顯示同尺寸預計份數，確認後取代畫布；可復原。容量限制須說明，不可暗中縮小貼紙。 |
| 自動排版 | 維持尺寸與白邊，圖案不得重疊，刀模之間至少 3 mm。MVP 預設方向朝上；未經使用者同意不自動旋轉。 |
| 排不下 | 說明縮小或減少份數，維持原畫布。 |
| 手機 | 點選設定與單指拖曳分工清楚；畫布外正常捲動。未提供縮放時應明示，不得攔截整個頁面的手勢。 |
| 空畫布 | 引導上傳或選擇素材，禁止空訂單。 |

正式版以刀模輪廓計算間距與碰撞；原型使用旋轉後矩形包圍盒作保守檢查，可能把形狀互補的配置視為間距不足。安全區座標必須以實機對位測試定版，不以介面示意線直接作為生產參數。

## 13.5 印製確認與總價

付款前必須展示設計預覽、每個圖案寬高、白邊與份數、材質、整板張數、商品小計、配送方式、運費、總額與預估出貨日。明確解釋半斷裁切會交付整張底紙，圖案可逐張撕下；確認螢幕與印刷可能存在色差。

| 檢查 | 產品處理 |
| --- | --- |
| 無素材、檔案遺失、無有效刀模 | 阻擋付款，引導重新加入或處理素材。 |
| 超出安全區、輪廓重疊、刀模間距不足 | 阻擋付款，回到畫布修正。 |
| DPI 150–299 | 提醒細節較柔和，要求確認後可繼續。 |
| DPI 低於 150 | 顯著提醒可能模糊，建議換圖，明確確認後可繼續。 |
| 背景處理失敗但原圖可用 | 可選保留原圖，通過原圖刀模檢查後繼續。 |
| 色差與半斷交付 | 在確認頁說明並要求確認設計，避免期待落差。 |

總價在付款前固定並保存；運費變更必須重新顯示總額。頁面預估出貨與實際物流到貨分開呈現；2 個工作天出貨是待驗證服務目標，需考慮付款確認、假日、產能與客戶確認所增加的時間。原型採 NT$200／A4、超商 NT$60／郵局 NT$40 的示範值，不代表供應商正式報價。

## 13.6 草稿、自動保存與訪客體驗

草稿保存移至 MVP，取代第 9 章將完整存檔全部延後的安排。MVP 先做到同裝置自動保存，完整雲端與跨裝置同步再擴展。

- 內容變更後自動保存，顯示處理中、已保存與保存失敗。
- 同裝置預設保留 30 天（以最後保存時間計）；重開頁面恢復素材、位置、尺寸、背景模式、材質與張數。
- 儲存空間不足時不能宣稱已保存；應提示減少素材或縮小圖片。
- 清除瀏覽器資料、使用無痕或更換裝置可能失去本機草稿，必須說明。
- 正式雲端訪客草稿需安全且有限期的存取方式；登入後可認領，不使用 email 或可猜測 ID 當成唯一存取控制。
- 保存時間、檔案保留與過期提示須一致；不要將失效來源圖恢復成可下單狀態。

## 13.7 訂單快照與資料模型補強

### 快照時點與不變性

正式系統在建立待付款訂單時凍結此次結帳版本，在付款確認時再次驗證該快照的金額與有效性。此設計取代先前只關聯可編輯 Design 的做法，可避免付款前後編輯造成訂單內容漂移。

快照包含原圖及處理結果引用、畫布 JSON、物理尺寸、白邊、份數、材質、預覽、商品與配送金額、製作參數版本、建立時間與內容校驗值。生產 PDF/SVG/DXF 記錄所使用的快照版本，且產出版本不可覆寫舊檔。

付款後禁止直接修改快照；需要更正時，以重新確認的新版本與可追蹤的訂單處理紀錄完成，不靜默變更。重新訂購從歷史快照產生獨立草稿，再檢查目前價格、材料與來源檔案是否仍可用。

### 第 6 章模型新增項目

| 實體 | 需要補充的資料與約束 |
| --- | --- |
| Design / Draft | 訪客擁有者或 User 關聯、revision、expiresAt、lastSavedAt、來源素材引用；訪客訂單不強制 userId。 |
| Asset | 原始與處理後檔案引用、像素寬高、格式、處理狀態、任務錯誤與保存期限。 |
| OrderDesignSnapshot | 不可變 canvasJson、素材引用、預覽、規格版本、checksum、createdAt；OrderItem 必須關聯此實體。 |
| Order | currency、subtotal、shippingFee、totalAmount、shippingMethod、預估出貨日、付款期限與聯絡資料。 |
| PaymentAttempt / PaymentEvent | 金流識別碼、金額與幣別、成功／失敗／逾期、唯一事件鍵；重複通知不可重複生產。 |
| RenderJob / ProductionFile | 快照 ID、參數版本、嘗試次數、檔案引用、checksum、錯誤、人工處理紀錄。 |
| OrderStatusEvent | from/to、操作者、時間、原因；只允許合法狀態轉移。 |
| Shipment / Refund / Reprint | 追蹤資料、原因、數量、金額、完成時間與與原訂單的關聯；補寄不覆寫首次出貨歷史。 |

金額以整數最小貨幣單位保存；本專案 TWD 示範以整元計價。正式價格由伺服器計算並驗證，不接受前端指定總價。涉及個資與付款之正式安全、條款與保存政策須另行審核後上線。

## 13.8 異常狀態、客服與工坊後台

生產、付款、退款與物流應各有獨立狀態，避免以單一枚舉表示互相重疊的流程。使用者顯示簡單可理解的進度；內部記錄完整事件。原型使用簡化狀態機演示。

- 付款失敗可在有效期限內重試；逾期訂單不可直接復活成已付款，要重新結帳。
- 金流回呼以唯一事件鍵、金額核對與交易識別做到冪等；失敗或重複通知不可觸發重複渲染。
- 渲染失敗可有限次重試；仍失敗轉人工處理，不遺失原付款資料。
- 圖片或生產檔有疑慮時進入待客戶確認，記錄原因、通知與確認結果，重新估計出貨時間。
- 印裁失敗記錄原因、報廢數量、重製數量與新生產批次。
- 取消與退款依付款及生產狀態處理；正式取消窗口、退款責任與售後政策須在結帳前提供，不能只靠客服臨時判斷。
- 物流異常可記錄追蹤與聯絡結果；補寄與退款各自保留處理事件。

MVP 工坊後台包含訂單篩選、不可變快照預覽、印製資訊核對、版本化 PDF/SVG/DXF 下載、渲染重試、待確認、印裁／包裝／出貨紀錄、追蹤編號、重製原因、退款處理與基本權限。原型只提供快照 JSON 下載及本機流程模擬，不能用於實際印裁、收款或退款。

正式後台依角色限制付款／退款與生產操作；任何異常轉移要求記錄原因。尚未生產的取消、已付款退款與物流補寄要有可查詢結果，並對客戶提供明確下一步。

## 13.9 事件、指標與驗證

補充第 12 章的事件定義，目標值先視為假設，以真實試營運資料調整。

| 指標 | 事件與觀察方式 |
| --- | --- |
| 首次完成時間 | first_upload 至 first_valid_sheet；首次有效貼紙板為通過印製檢查的非空畫布。 |
| 去背品質 | started / succeeded / failed / retried / reverted，按素材格式與失敗原因統計；不記錄圖片內容。 |
| 排版可用性 | pack_completed 後是否手動移動／縮放，及 pack_failed 原因。 |
| 下單阻擋 | preflight_failed：安全區、間距、空素材、來源遺失等；記錄類型而非個資。 |
| 運費流失 | shipping_total_viewed 至 payment_started 的轉換，區分配送方式。 |
| 付款品質 | payment_started / succeeded / failed / expired / duplicate_callback。 |
| 履約與客訴 | render_failed、reprint、shipping_exception、refund，按尺寸、色差、去背與裁切原因分類。 |

原型事件只存於本次頁面記憶體，可在工坊示範查看；不是正式分析服務。正式事件資料應最小化、避免保存圖片、收件地址或支付資料，並定義 session、首次使用者與各事件去重方式。

## 13.10 調整後 MVP 順序與驗收

1. 原圖／去背選擇、比較、還原與失敗處理。
2. 基本編輯、同圖份數／排滿與可復原的排版檢查。
3. 免登入開始、草稿自動保存及恢復。
4. 完整印製確認、材質、總價、配送與出貨預估。
5. 訂單不可變快照與重新訂購。
6. 工坊後台、異常履約、事件與品質指標。

原第 7 章的演算法 PoC 與實體印裁驗證仍需先行；介面與失敗流程可同步驗證。金流與物流在完整快照與狀態規則具備後串接；市集、分潤、特殊材質與完整會員擴展延後。

驗收至少涵蓋：第一次使用者無協助完成有效貼紙板；重整恢復草稿；排不下不縮小尺寸；原圖不被失敗去背破壞；未解決阻擋不得下單；警告須明確確認；後續編輯不改變已建立訂單；重複付款事件只觸發一次生產；渲染／印裁／物流失敗可追蹤與恢復。

## 13.11 原型對照與開放議題

`prototype/` 實作生活／商用入口、原圖選擇與示範去背比較、寬高與旋轉、指定新增份數、同圖排滿、同裝置自動存稿、保守印製檢查、解析度確認、配送總價、獨立本機訂單快照、重新編輯與工坊異常流程。

尚待正式開發：AI 模型、HEIC、精確輪廓排版與刀模、伺服器保存與權限、真實付款冪等、收件資料與門市地圖、電子發票、版本化印刷檔、客服通知、正式分析服務與負載測試。啟動試營運前須確認實體材料表現、最小可裁尺寸、刀模安全區、實際配送費率、產能與取消／退款政策。
